# FQ4R 부대 헤더 형식

영속 부대 영역은 파일 `0x59A6~0x79A5`다. 레코드는 16바이트 헤더와 인원×2바이트 멤버 참조로 구성된다. 아래 오프셋은 각 레코드 시작 기준이다. 전투용 부대 배열은 구조를 복사한 뒤 필드를 다른 뜻으로 덮어쓰므로 구별해야 한다.

## 전체 바이트

| 오프셋 | 형식 | 확인된 용도 | 확실성 |
|---|---|---|---|
| +00 | u8 | 하위 4비트 소속, 상위 4비트 부대 생명주기/대기 상태. FE 전투 전환 표시, FF 목록 종료 | 사용 경로 확인, 전체 enum 미확정 |
| +01 | u8 | 부대원 수. 다음 레코드 = 현재 +16+인원×2 | 확정 |
| +02 | u8 | 현재 외부 지역 번호 또는 맵 ID 하위 바이트 | 확정 |
| +03 | u8 | 아군은 맵 ID 상위 바이트. 비아군 전투 변환 경로에서는 전투 능력치 가산 계수 | 해당 경로 확정 |
| +04 | u8 | 활성 부대의 맵 진입 배치 코드 / 대기·복제 원본 부대의 출현 대기 카운터 | 복수 용도 확정 |
| +05 | u8 | 상위 4비트 국가 표시·집계 그룹, 하위 4비트 이벤트의 소속 변경 대상 그룹 | 동작 확인, 원 소속 국가라는 이름은 추정 |
| +06 | u8 | 부대 식별 번호 | 확정 |
| +07 | u8 | 미확정. 전투 전환 경로에서 bit80이 켜져 있으면 전체 바이트를 0으로 초기화 | 일부 동작만 확인 |
| +08 | u8 | 미확정, 원본 보존 | 미확정 |
| +09 | u8 | 미확정, 원본 보존. +08과 묶인 캐릭터 참조라는 이전 가설은 확정할 수 없음 | 미확정 |
| +0A | u8 | 이동 목표/명령. 00 없음, 일반 값 목적 지역, FE 주인공 부대 추적, FF 주변 부대에 따른 목표 선택 | 특수값 처리 확정 |
| +0B | u8 | 복제 생성된 부대가 참조하는 원본 부대 ID | 복제 경로 확정 |
| +0C | u8 | 이전/복귀 맵 ID 하위 바이트 | 확정 |
| +0D | u8 | 이전/복귀 맵 ID 상위 바이트 | 확정 |
| +0E | u8 | 상위 4비트가 전역 진행 플래그 검사 번호. 부대 이동/출현 허용 조건에 사용 | 검사 경로 확정, 플래그별 사건 미확정 |
| +0F | u8 | 미확정 | 미확정 |

## +03: 맵 상위 바이트와 비아군 강화 계수

소속값이 0이면 +02/+03의 u16 맵을 사용하고, 다른 소속이면 +02만 사용한다. 비아군 이동에서는 +03을 맵 상위 바이트로 덮어쓰지 않는다.

비아군 전투 변환 시 +03의 값 n으로 다음 가산을 수행한다.

- n=0이면 HP 가산 0, 그 외 `3*n + 2*(rand() % n)`.
- 전투 유닛의 두 HP 워드에 위 값을 더한다.
- AT·AR·DF·DR에 각각 `n >> 2`를 더한다.

이것은 해당 전투 변환 경로의 공식이다. 캐릭터 영구 능력치나 모든 게임 모드에 적용된다고 일반화하지 않는다. 이 가산에는 99/999 제한이 적용되지 않는다. 따라서 비아군의 +02/+03을 일반적인 u16 위치 값으로 편집하면 강화값까지 바꿀 수 있다.

## +04: 진입 배치와 출현 대기

이전 위치를 +0C/+0D에 보관하고 연결 지역 테이블에서 새 맵과 이전 맵을 확인한 결과(0/1/2)를 +04에 쓴다. 방위(동서남북)라는 이름은 아직 근거가 부족하다.

상위 상태가 D0(복제 원본) 또는 10(대기)인 레코드에서 +04를 감소시키고 0이 되면 출현 후보로 삼는다. 복제 후 원본은 10으로 재설정하며 전역 옵션에 따라 1로 설정한다. 생성된 활성 부대에는 FF를 쓴다. 이 카운터의 1단위가 실제 몇 초인지는 확인하지 않았다.

## +05: 두 개의 소속 그룹

상위 니블로 국가별 수를 집계하고 지도 표시를 고른다. 상위 니블을 부대 표시 팔레트 선택에 사용한다.

하위 니블이 이벤트 인자와 일치하는 부대를 찾아 +00의 소속을 변경한다. 이후 +05의 하위 니블은 유지하고 상위 니블을 1로 바꾼다. 따라서 상위는 현재 표시 소속, 하위는 원 소속 국가일 가능성이 높지만, 하위 전체 코드의 국가명 대응은 아직 확정하지 않았다. 기존의 전술/진형 값이라는 추정은 수정한다.

## +0A와 +0B: 명령과 복제 원본

FE는 ID0 부대의 위치를 목적지로 삼는다. 내부 맵이면 상위 지역 변환 테이블을 거친다. FF는 주변 지역·부대·진영 관계 검사 결과를 목적지로 사용한다. 일반 목적지 도착이나 경로 실패 시 명령을 지우는 경로가 있지만 FE는 유지한다.

D0 원본을 복사하고 생성 부대에 새 ID를 할당한 뒤 +0B에 원본 ID를 기록한다. 활성 부대들의 +0B를 원본 +06과 비교하여 이미 생성된 부대가 있는지 확인한다. +0B를 바꾸면 중복 출현 방지 관계가 달라질 수 있다.

## +0E: 진행 조건

값이 0이면 조건을 통과한다. 0이 아닌데 상위 니블이 0이면 해당 검사에서 통과하지 않는다. 상위 니블 k가 있으면 다음 마스크를 사용한다.

```text
mask = 1 << k
mask = ((mask & 0xFF) << 8) | (mask >> 8)
허용 = (진행플래그 & mask) != 0
```

위 계산에서는 마스크의 바이트 순서를 바꾼다. 하위 니블의 별도 의미와 각 진행 비트에 대응하는 사건 이름은 확인하지 못했다. +0E/+0F를 하나의 u16 값으로 취급할 근거는 없다.

## 미확정 필드와 편집 범위

+08/+09는 정렬된 캐릭터 참조처럼 보이는 샘플도 있지만 `0x4082`처럼 0x20 비정렬 값도 있다. 전투 배열의 같은 위치는 원래 부대 상태와 전투 인덱스로 덮어써진다. 또한 전투→영속 변환은 이 두 바이트를 명시적으로 기록하지 않는다. 따라서 전투 배열의 뜻을 세이브 필드에 그대로 적용하거나 리더 포인터로 노출하면 안 된다.

+07은 80 처리 외의 비트 의미, +0F는 의미 있는 사용 경로를 찾지 못했다. 0으로 초기화하는 코드는 용도 전체를 증명하지 않는다. 에디터에서는 원본을 보존하고 필요시 원시 바이트로만 다루는 것이 타당하다.

## enum·비트 필드의 값과 용도

아래 값은 모두 16진수다. 상위·하위 니블은 각각 하나의 코드 값이며 독립적인 체크박스 플래그로 취급하지 않는다. 알려진 동작과 미확정 레이블을 구분한다.

### +00 — 진영과 부대 상태

| 구분 | 추출식 | 용도 |
|---|---|---|
| 하위 니블 | `value & 0x0F` | 전투 진영 관계 조회 |
| 상위 니블 | `value & 0xF0` | 활성·대기·복제 원본 등의 상태 구분 |

| 값 | 확인된 용도 |
|---|---|
| 상위 00 | 활성 부대 처리 대상 |
| 상위 10 | 출현 대기 처리 대상 |
| 상위 D0 | 부대를 복제하여 출현시키는 원본 |
| 전체 FE | 영속 부대를 전투 배열로 옮긴 뒤 기록하는 표시 |
| 전체 FF | 부대 목록 종료 표시 |
| 전체 00 | 플레이어 활성 부대 필터에 사용 |
| 전체 01 | 기존 확인된 바르시아 측 분류 |
| 전체 D1 | 복제 원본 상태 D0와 진영 01의 조합 |

에디터의 “D1 양산형”은 편의상 붙인 레이블이다. 30·31·34·35 등도 관측되지만 상위 30은 추가 추적에서 비활성 상태로 확인했다. 각 사건의 원인과 복귀 시점은 미확정이다. 국가명 테이블을 +00 원시 값으로 직접 조회하면 안 된다.

### +04 — 진입 배치 코드 / 출현 대기 카운터

활성 부대의 맵 이동 경로에서는 다음 결과를 기록한다.

| 값 | 동작 |
|---|---|
| 00 | 연결 지역 검사에서 기본 결과 |
| 01 | 첫 번째 연결 지역 목록에 해당 |
| 02 | 두 번째 연결 지역 목록에 해당 |

동·서·남·북 같은 방향명은 미확정이다. 대기·복제 원본 부대에서는 enum이 아니라 감소하는 카운터로 사용한다.

| 값 | 동작 |
|---|---|
| 00 | 다른 조건도 충족하면 출현 후보 |
| 01 이상 | 검사 시 감소하며 0이 되면 출현 후보 |
| 0A | 복제 후 원본의 기본 재대기 값(10진수 10) |
| 01 | 특정 전역 옵션에서 사용하는 재대기 값 |
| FF | 출현 처리 후 활성 부대에 기록 |

카운터 1단위가 실제 몇 초에 해당하는지는 확인하지 않았다.

### +05 — 국가 그룹

| 마스크 | 용도 |
|---|---|
| F0 | 상위 니블: 국가별 집계·지도 표시·팔레트 선택 |
| 0F | 하위 니블: 이벤트 소속 변경 대상 및 전투 관련 국가명 선택 |

하위 니블이 참조하는 국가명 테이블은 다음과 같다.

| 코드 | 국가 | 코드 | 국가 |
|---|---|---|---|
| 0 | 카리온 | 8 | 제므 |
| 1 | 바르시아 | 9 | 베닉크 |
| 2 | 휴리아 | A | 모로시아 |
| 3 | 물톤 | B | 노호크 |
| 4 | 그레이스 | C | 에드윈 |
| 5 | 레스터 | D | 마시아 |
| 6 | 사네트 | E | 세버트 |
| 7 | 링커 | F | 벨더 |

상위·하위를 모든 상황에서 “현재 국가 / 원래 국가”라고 부를 수 있는지는 미확정이다. 상위 니블의 모든 값에 위 국가명을 그대로 적용할 수 있다는 뜻도 아니다. 국가명 테이블의 10(중립국)은 4비트 필드에 직접 들어가는 값이 아니다.

### +0A — 이동 명령

| 값 | 용도 |
|---|---|
| 00 | 이동 명령 없음 |
| 일반 지역 번호 | 지정 지역으로 이동 |
| FE | ID 0인 주인공 부대의 위치 추적 |
| FF | 주변 지역·부대·진영 관계를 검사하여 목표 선택 |

FE·FF는 지역 ID로 해석하지 않는다.

### +0E — 진행 조건 코드

이 바이트 자체가 여러 독립 플래그를 담는 것은 아니다. 상위 니블이 전역 진행값의 검사 대상을 선택한다.

| 값 또는 상위 니블 | 검사하는 전역 마스크 / 동작 |
|---|---|
| 전체 00 | 진행 조건 없음 |
| 전체 01~0F | 조사한 경로에서 조건 통과하지 않음 |
| 상위 1 | 0200 |
| 상위 2 | 0400 |
| 상위 3 | 0800 |
| 상위 4 | 1000 |
| 상위 5 | 2000 |
| 상위 6 | 4000 |
| 상위 7 | 8000 |
| 상위 8 | 0001 |
| 상위 9 | 0002 |
| 상위 A | 0004 |
| 상위 B | 0008 |
| 상위 C | 0010 |
| 상위 D | 0020 |
| 상위 E | 0040 |
| 상위 F | 0080 |

예를 들어 +0E=60이면 전역 진행값의 4000 비트가 켜져 있어야 해당 조건을 통과한다. 각 비트가 어느 사건을 의미하는지와 하위 니블의 별도 용도는 미확정이다. 계산식은 위의 진행 조건 설명을 참고한다.

### +07 — 일부 동작만 확인된 플래그

| 마스크 | 확인된 동작 |
|---|---|
| 80 | 특정 전투 전환 경로에서 켜져 있으면 해당 바이트 전체를 00으로 초기화 |

이 비트의 의미를 설명하는 레이블과 나머지 비트의 용도는 미확정이다. 단순히 bit80만 지우는 동작과 바이트 전체 초기화는 구별해야 한다.

## 부대 목록의 국가 표시

목록 NATION은 +05 하위 니블의 국가명과 +00 소속을 함께 표시한다. +00=00 부대를 먼저 부대 ID순으로 표시하고, 나머지는 +05 하위 니블 국가 코드순, 동일 국가 내에서는 부대 ID순으로 표시한다. 정렬은 화면에만 적용한다. 글자색은 국가명과 동일한 +05 하위 니블에 대응하며, 사용자가 제공한 게임 화면 국가 범례의 색상 사각형 내부 RGB를 추출한 값이다. 국가명도 화면 표기에 맞춰 물톤·사네트로 수정했다.

| 국가 코드(하위 니블) | 팔레트 인덱스 | RGB |
|---|---|---|
| 0 | 01 | #F7F7F7 |
| 1 | 03 | #F70000 |
| 2 | 04 | #F7F700 |
| 3 | EF | #0000F7 |
| 4 | E2 | #19945A |
| 5 | E1 | #E600E6 |
| 6 | E0 | #00C5F7 |

링커(7)는 휴리아와 같은 #F7F700, 제므·베닉크·모로시아·노호크·에드윈·마시아·세버트·벨더(8~F)는 바르시아와 같은 #F70000을 사용한다. 이는 사용자 지정 표시 규칙이다. +00 기반 아군 필터와 특수 부대 판정은 별도로 유지한다.

### 소속·활동 상태 표시

+00 하위 니블 0은 아군, 1은 적군, 4·5는 에디터의 중립 분류입니다. 상위 니블 30은 비활성, D0는 양산형입니다. 상태 30·31·34·35는 하위 소속이 서로 달라도 모두 비활성으로 표시합니다. 특정 사건명·사망·해산을 뜻한다고 단정하지 않습니다.

목록의 접미사는 비활성일 때 `(비활성)`을 우선합니다. 그 외 카리온이 아닌 아군은 `(아군)`, 양산형은 `(양산형)`을 표시합니다. `(적군)`, 중립 표시, 원시 상태 코드는 목록 텍스트에 붙이지 않습니다. 원시 +00·+05는 메인 목록의 툴팁과 편집 모달에서 확인합니다.

메인 NATION은 180px 고정폭이며 초과 시 말줄임표를 사용합니다. 비교 부대 선택 목록은 별도 반응형 폭을 사용합니다. 국가명·색상은 모두 +05 하위 니블 기준입니다. 예를 들어 +05=15 레스터는 보라색이며 상위 니블 1의 빨간색을 쓰지 않습니다.

비활성 부대는 지도 표시·일반 자동 이동·통상 전투 편성에서 제외됩니다. 출현 대기 10 및 양산형 D0와 다릅니다. 이벤트 전까지 부대를 보관하는 상태로 취급하며 인원과 부대원 참조는 유지합니다. 상태의 정확한 변경 사건과 복귀 시점은 미확정입니다.

편집 UI와 목록 필터의 현재 규칙은 [부대 편집 UI와 데이터 동작](TROOP_EDITOR_DESIGN.ko.md)에 정리했습니다.
