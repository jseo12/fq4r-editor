# 부대 편집 모달

부대 목록의 행을 클릭하거나 Enter/Space를 누르면 편집 모달을 엽니다. 변경은 메모리에 즉시 반영하며, 파일 기록은 기존 저장/다운로드 버튼으로 수행합니다.

## 편집 항목

구체적인 필드·저장 위치·범위와 상태별 동작은 [부대 편집 UI 설계와 구현](TROOP_EDITOR_DESIGN.ko.md)에 기술했다.

- 소속과 활동 상태는 +00의 하위·상위 니블을 각각 편집한다.
- 국가와 국가 표시 그룹은 +05의 하위·상위 니블을 각각 편집한다.
- NO, 상태별 현재 위치, 비아군 전투 강화값, 이동 명령과 목적지를 제공한다.
- 추가 부대 정보는 접이식으로 진입 배치/출현 대기값, 복제 원본 ID, 이전 위치, 진행 조건, 원시 HEX를 제공한다.
- 상단에 최초 파일과 비교한 16바이트 HEX 및 변경 강조를 표시한다.
- 부대 편성 탭은 현재 부대와 최대 제5부대까지의 비교 목록으로 구성한다. 행 선택·드래그·NEW 행으로 교환·이동·추가하며, 더블 클릭하면 캐릭터를 편집한다. RESET은 확인 후 최초 데이터로 복원한다.

## 직렬화와 검증

부대 영역은 `0x59A6~0x79A5`의 8192바이트입니다. 각 부대는 `16바이트 헤더 + 인원수×2바이트 캐릭터 참조`이고 마지막에 FF 종료 표시가 있습니다. 참조는 캐릭터 NO가 아니라 `NO×32`인 little-endian u16입니다.

편집한 부대의 인원이 달라지면 뒤쪽 레코드의 위치를 재배치합니다. 부대의 논리 순서와 다른 부대의 헤더·부대원은 유지하며, 수정된 범위 뒤의 패딩도 보존합니다. 줄어든 레코드가 차지하던 빈 공간은 0으로 비웁니다. 체크섬 표는 기존처럼 로딩 시점의 검사 결과를 유지하며 실제 저장 시 전체 체크섬을 계산합니다.

- 인원 수의 저장 형식 상한은 255명입니다. UI에서 NEW로 추가하는 상한은 18명이며, 이미 더 많은 인원이 있는 부대를 임의로 자르지 않습니다.
- 부대원 선택값은 0~639의 정수여야 합니다. UI는 파서가 읽은 고정 캐릭터와 활성 동적 캐릭터를 제공합니다.
- 원본 게임에서 템플릿 중복 참조가 존재하므로 부대원 중복을 일괄 삭제하거나 전역 중복으로 거부하지 않습니다.
- 저장 영역에 종료 표시까지 들어갈 공간이 없으면 편집을 거부하며 데이터는 변경되지 않습니다.
- 의미가 확인되지 않은 헤더 필드는 자동 수정하지 않습니다. MAP 편집은 이 부대의 맵 ID만 변경하며 플레이어 전역 맵이나 캐릭터의 아군·수감 플래그를 자동 동기화하지 않습니다. 게임의 정상 이동 명령 전체를 재현하는 기능은 아닙니다.

부대 크기 변경·참조 인코딩·다른 부대 보존·용량 초과·원복은 단위 테스트로, 실제 다운로드 파일을 다시 읽는 과정은 브라우저 테스트로 검증했습니다. 편집된 모든 조합을 실제 게임에서 실행해 검증한 것은 아닙니다.

## 헤더 형식

[부대 헤더 형식](TROOP_HEADER.ko.md)에 상태별 필드 용도를 정리했다. 비아군 +03은 전투 강화 계수로 사용되므로 현재 UI는 위치(+02)와 강화값(+03)을 분리한다.
